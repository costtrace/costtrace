Why CostTrace

Designed for a different question.

CostTrace is an open-source, local-first tool that measures how the changes you ship coincide with changes in your actual cloud bill, using your own FOCUS data, in your own CI. Estimators ask what a change should cost; budgets ask whether spend moved; FinOps platforms ask where the money went. CostTrace asks, right in the pull request: what did this change actually do to the real bill?

Measured, not guessed

What each change actually cost, read from your bill with your negotiated rates, not list-price estimates.

Per pull request, even for code

Cost changes are lined up with the deploys they coincide with, including changes with no infrastructure diff at all.

Open and transparent

Open source, runs on your own FOCUS export in your CI, and every figure comes with a ± range and a documented method.

Ask your coding agent what a change cost

CostTrace ships an MCP server, so Claude Code, Cursor, VS Code and other agents answer cost questions with numbers measured from your bill instead of guesses, and can trace a spike back to the deploys and diffs it coincides with.

What it catches

Every deploy, measured from the bill, whether the change was infrastructure, code or a clean-up.

New & resized infrastructure

A NAT gateway estimated at $310/mo that really costs $1,368, because data processing never shows up in a Terraform plan.

Application code

Queries, retries, log volume or LLM calls that raise the bill of unchanged resources, attributed to the PR that deployed them.

Savings

Deleted and downsized resources count as savings, so clean-up work gets the credit it earns.

Only real signals

Every figure has a ± range from daily variation, noise isn't listed as impact, and back-to-back deploys are kept apart.

How it works

No agents and no SaaS account. CostTrace runs in your CI or on your laptop against your own billing export.

  1. Tag

    Deploys stamp resources with costtrace_sha, _pr, _repo and _service. One convention that's valid on every cloud.

  2. Measure

    CostTrace reads your FOCUS export straight from S3, Blob Storage or BigQuery and compares costs before vs. after each deploy.

  3. Attribute

    New, changed and removed resources, plus cost shifts from application code in the same service, each with a ± range.

  4. Report

    Post a PR comment, print a table, export JSON, or fail CI when a change blows past its estimate.

One tool, every cloud

CostTrace is built on FOCUS, the FinOps Foundation's open billing standard that every major cloud now exports. Point it straight at the export: no data pipeline, no copy.

AWSData Exports in S3s3://bucket/prefix

Reads CSV, gzipped CSV and Parquet, fetching only the columns and billing months a report needs. Two million billing rows take about five seconds.

Try it in a minute

Install the CLI and the connector for your cloud. No cloud account handy? The repository ships a multi-cloud sample dataset.

# the CLI, plus the connector for your cloud (aws, azure or gcp)
$ npm install costtrace @costtrace/aws

# why did cost change this month? usage vs. rate vs. new resources, and which deploys coincide
$ npx costtrace explain --focus s3://my-billing/focus/data/ --month 2026-09 --changes changes.json

# measure every change in a deploy log, straight from your billing export
$ npx costtrace report --focus s3://my-billing/focus/data/ --changes changes.json

# a PR comment for one change; fail CI if it's over estimate
$ npx costtrace report --focus s3://my-billing/focus/data/ --changes changes.json \
    --sha 7d24e0c --format markdown --fail-on-over

# the tags your IaC should apply
$ npx costtrace tags --sha "$GITHUB_SHA" --pr 104 --service checkout --format terraform
